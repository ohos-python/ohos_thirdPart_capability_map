# 场景目录 V1

打开 `index-v1.html` 即可使用。新增页面独立于原版，`index.html` 及现有适配数据保持不动。GitHub Pages部署后可直接访问仓库站点下的 `/index-v1.html`。

## 页面内容

- 15个能力大类，每类8个具体任务，共120个基础候选场景。
- 15个跨领域候选，包括IoT、机器人、工业控制、区块链、金融、医疗、HPC、数字孪生、企业管理、协同、教育、搜索推荐、物流、EDA、XR。
- 每项都有任务目标、能力链、系统或外部依赖、验收目标和决策备注。
- V1保留7,648条有项目来源的“能力大类—库”关系和4,755个唯一库，不加入没有来源记录的人工库。逐库根据官方/目录功能描述在120个基础场景中全局匹配；无细分功能命中时按项目所属大类回退并明确标记“需复核”。
- 当前功能直接匹配4,387条关系，需复核3,261条关系。跨领域场景只纳入功能描述明确命中的库，不把关联大类全部复制进去。每张场景卡独立统计识别库、主要来源语言、已完成、进行中、确认缺口、数据缺失、功能匹配和需复核数量。
- 每个来源库展示项目记录中的来源语言、项目引用数和鸿蒙化状态。逐库功能优先引用联网采集的 npm、PyPI、Homebrew 官方元数据并提供原始链接，其次使用Python/C++目录说明；缺少逐库元数据时明确显示数据缺失。当前2,903个唯一采集目标中2,686个取得官方功能描述。列表支持按库名、来源语言、功能证据或状态筛选。
- 当前进度口径：Python 目录命中项记为已完成；C/C++ 与 Node.js 工作项统一记为进行中；Go、Java、Rust 数据缺失。Python 未命中当前完成目录的条目记为确认缺口；进行中、待核验和数据缺失不计入确认缺口。
- 所有场景默认“待决策”，没有提前排除场景。场景功能分配不等于鸿蒙端到端适配通过；验收状态仍为“未评估”。候选清单不宣称穷尽全部开发场景。
- Go、Java、Rust 当前统一标记为“数据缺失”，待取得对应鸿蒙三方库目录后再评估；数据缺失不等于不支持，也不作为0%场景覆盖率。
- 原研究表的统计用于研究底稿，不当作鸿蒙的场景适配率。

## 运行依赖

页面依赖同目录下的五个静态文件：`scenarios-v1.css`、`scenarios-v1-data.js`、`scenarios-v1-coverage.js`、`scenarios-v1-library-candidates.js`、`scenarios-v1.js`。不需要服务端、构建命令或第三方CDN，本地文件和静态网站均可使用。

原版链接与研究表链接属于辅助导航；场景目录不需要加载原版Python、C/C++或项目满足度数据库。

## 决策保存与分享

范围状态为“待决策 / 本期纳入 / 后续考虑 / 暂不需要”。这是需求范围，不是适配进度。

状态和备注使用当前浏览器的localStorage保存，键为 `ohos-scenario-scope-v1`。不会改写仓库文件、原版地图，也不会自动同步给其他人。浏览器存储受限时页面会提示，只能在本次页面会话中保留。

更换设备、浏览器、页面地址或由本地切换到GitHub Pages前，应导出JSON备份。导出包含全部135个场景、稳定编号和决策；导入先验证目录版本、编号和字段，再经确认合并同编号决策。没有重置或删除原始场景的操作。
